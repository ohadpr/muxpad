Per-workspace instructions, and capabilities that are off by default

Right now readAgentInstructions(dataDir) takes a directory and nothing else — so every agent in every workspace gets byte-identical text, including the Slack section. A Personal chat is told it has company Slack and only finds out otherwise when it tries. This is the panel that fixes that.

Reached from the workspace row in the nav (⋯ → Settings) or the breadcrumb. Shown below for both of your real workspaces, because the difference between them is the whole point.

What this replaces, and what it costs

The slack-allowed-workspaces file is gone — the toggle is the allowlist, stored on the workspace row, so there is one place to look and the UI cannot disagree with the file. Reading gets gated the same way as posting, which it is not today: a Personal pane can currently run muxpad slack channels and list every private channel you are in.

The one real change underneath: readAgentInstructions() takes no context today — that is why every agent gets the same text. It needs the pane's workspace, which all three backends already know, so it is threadable. It is the first time that file stops being one global blob, which is worth saying out loud because everything downstream assumes it is.

And the key — what actually stops a Personal chat finding it

Nothing above does. The guard is in the CLI; the token is in a file, and every pane runs as the same uid you do. An agent asked to post from a Personal chat can read ~/.claude/secrets/slack.env and curl Slack directly. I verified that.

So the honest answer to "make it impossible" is a second uid, and everything short of that is making it harder and louder rather than impossible. The toggle above is worth doing regardless — it removes the temptation and the accident, which is the realistic risk — but it should not be described as a sandbox.
